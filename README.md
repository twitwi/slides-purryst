# SlidesPurryst

Where Typst meets Vue to craft purr-fect slide decks.

A presentation framework allowing the use of Vue 3 components. The framework handles scaling, stepping, animations, transitions, presenter mode, live reload, and export.

Slides can be authored as either HTML-like markup directly in a `<script>` tag, or using typst (or other markup languages) to generate the HTML-like markup.
The HTML-like markup is a superset of HTML, with custom `<sp-*>` components for slides, steps, animations, and other presentation features.
Originally meant to be an intermediate format for typst, the HTML-like markup can also be authored directly (or generated by other tools).

## Quick Start

There are several ways to use SlidesPurryst, depending on your needs and preferences.
The recommended gives you a minimal setup with live reload, and is the easiest to get started with.

Below you will see `github:twitwi/slides-purryst#latest` as argument to `pnpm add`. You can also use a fork or a local clone, or `twitwi/slides-purryst` (for the version from the npm registry, when published there).



### Recommended for typst

``bash
mkdir my-talk
cd my-talk
pnpm init
pnpm add 'github:twitwi/slides-purryst#latest'
```

Create a minimal typst file:


```typst
#import "slides-purryst/lib.typ": *

#slide[
  #h1[SlidesPurr(yst)]
  Where Typst meets Vue in purr-fect harmony.
]

#slide[
  = Part 1
]

```



### Minimal HTML file example

You can use as `index.html` the following content (or start from the "minimal" demo and/or pick content from the main demo):

```html
<!DOCTYPE html>
<html>
<head>
  <title>My talk</title>
</head>
<body>
  <div id="sp-presentation"></div>
  <script type="text/html" id="sp-content">
    <sp-slide><h1>Purr purr</h1></sp-slide>
    <sp-slide>
      <h2>Go!</h2>
    </sp-slide>
    <style>
    </style>
  </script>
  <script src="slides-purryst.bundle.js"></script>
  <script>SlidesPurryst.createSlidesPurryst({})</script>
</body>
</html>
```


### (recommended) Not so minimal standalone setting (HTML + bundle + package.json)

We will create a minimal npm project and install the `slides-purryst` package, which contains the bundle and a small server for live reload.

```bash
mkdir my-talk
cd my-talk
pnpm init
pnpm add 'github:twitwi/slides-purryst#latest'
```

Then

- edit `index.html` with your slides (see above)
- run `pnpm slides-purryst` to start a server with live reload


### Extremely minimal standalone setting (HTML + bundle)

- Create a minimal HTML file (see above) with your slides.
- Download  or copy a version of the `slides-purryst.bundle.js` next to your HTML file.
- Open as `file://`, no server needed.
- You don't get live reload, but you can edit the HTML and refresh the page to see changes.

WARNING about `file://` mode, any fetch request will fail so:

- loading custom vue components will not work,
- sp-include and sp-svg will not work, unless present in the sp-cache (typically if you exported as standalone from dev pane).



### (when published on npm) Easiest command line / CLI (no project, minimal install, zero setup if you have pnpx)

Just place your slides in `index.html` (see above) and run the server with live reload:

```bash
pnx --package=@twitwi/slides-purryst slides-purryst
```





### As an npm dependency (version pinned)

This mode is in-between the CLI case and the dev mode.
You work with the full power of Vite and the SlidesPurryst framework but without cloning the repo (so no modification to the framework source code).

```bash
pnpm init
pnpm add 'github:twitwi/slides-purryst#latest'
```

Create an `index.html` using ES module imports:

```html
...
<script type="module">
import { createSlidesPurryst } from 'slides-purryst'
import 'slides-purryst/style.css'
createSlidesPurryst()
</script>
...
```

Serve with live reload, edit support and vite:

```bash
pnpm sp-dev
```








### CLI(s) Options

**`slides-purryst`** (bundle-based static server), examples:

```bash
pnpm slides-purryst --port=8080 my-talk.html   # custom port and file
pnpm slides-purryst --watch ./slides --root .  # watch only a subdirectory, serve from root (so as /slides/... here)
pnpm slides-purryst --copy-bundle              # copy bundle to cwd and exit
pnpm slides-purryst --copy-agents              # copy agents.md to cwd and exit
pnpm slides-purryst --copy-fonts               # copy fonts and associated css to cwd and exit
pnpm slides-purryst --copy-fonts --copy-bundle --copy-agents
```

`--copy-bundle` copies `slides-purryst.bundle.js` to the current directory so you can open the HTML directly via `file://` without the server.
It is also a means of freezing the version of the framework for a given presentation.

`--copy-agents` copies `AGENTS.md` to the current directory so you can read the full reference offline.


**`sp-dev`** (Vite dev server for npm dependency projects), examples: 

```bash
pnpm sp-dev --port 8080 --no-open      # custom port, no auto-open
pnpm sp-dev --watch ./slides --root .  # watch only a subdirectory, serve from root (so as /slides/... here)
```




### Dev mode (clone & hack the framework)

```bash
git clone https://github.com/twitwi/slides-purryst.git
cd slides-purryst
pnpm install
pnpm dev
#pnpm build
```

Edit `example/demo-slidespurr.html`, Vite HMR refreshes on save.
You can also create your own HTML in the `example/` folder.

## Release via git tags

Update the version in `package.json`, commit, clean your tree, then run:

```bash
bash scripts/release.sh v0.1.0          # normal release, moves latest
bash scripts/release.sh --only-latest
bash scripts/release.sh --only-test
bash scripts/release.sh --no-latest v0.1.0  # backport fix to existing tag
```
